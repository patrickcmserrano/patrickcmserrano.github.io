Project Overview

Daelaam é a marca comercial: a entidade com CNPJ que assina contrato e carrega o nome que aparece para o cliente. A tecnologia tem nomes próprios em duas camadas. A Rohana é a engine: o core multi-tenant em Clojure que hospeda muitas personas isoladas, cada uma com a própria base de conhecimento, com as mensagens trafegando por um barramento de eventos (NATS JetStream) antes de virar resposta. E a Sofia (e futuras personas) é com quem o cliente final conversa — dado de tenant em EDN, nunca código. Sobre essa fundação rodam três subsistemas: o Agente (runtime conversacional WhatsApp/Telegram por tenant, com RAG sobre os documentos da própria empresa), o Probe (scraper de leads via OpenStreetMap → qualificação por 5 sinais → alerta no Telegram, com 88 leads validados em Niterói e zero custo de API — negócios que se expõem no OSM são auto-selecionados como digitalmente ativos) e o Observer (cockpit de operação e camada de dados/insight, planejado). Tudo desenhado com LGPD desde o início: trilha de auditoria em dois tiers e isolamento físico por tenant.

Architecture & Implementation

Cada mensagem entra por POST /webhook/:canal/:tenant, é normalizada em um envelope e publicada no barramento NATS JetStream (porta 4223 — a 4222 fica reservada ao ark-streams, do Nexus Quant, no mesmo VPS: máquina compartilhada, barramentos isolados). O subscriber consome e executa p.eql/process sobre o grafo Pathom 3 da Rohana, que resolve apenas o necessário para cada mensagem: tenant → intent → guardrail (horários por tenant) → rag → functions → llm → response/final. O retrieval é um microserviço Python (FastAPI) independente — hybrid search (dense + BM25 + RRF) com cross-encoder rerank e geração grounded — chamado via POST /query, o que permite escalar e versionar a pipeline RAG sem tocar no Clojure. A inferência tem provider configurável por EDN (NVIDIA NIM com Llama 3.3 70B em dev; Claude API em produção). O isolamento multi-tenant é físico: cada tenant tem a própria collection no Qdrant, derivada por um único chokepoint ("tenant_" + id) — uma busca na collection A nunca retorna dados de B, e um DROP COLLECTION apaga tudo de um cliente. Adicionar um tenant é escrever um .edn e indexar os docs: zero código, zero deploy.
